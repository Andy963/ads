# ADR 0011: Restore Cached Transcripts Before Auth and Resume by Cursor

## Status

Accepted

## Context

Issue #230 要求 PWA 在网络认证与 WebSocket 握手之前展示已读聊天，并避免无变化重连触发整份历史回放。现有同步系统已经具备持久化事件序列、HTTP 补偿、会话代数以及 ADR 0005 定义的运行态快照屏障，无需创建第二套同步协议。

单独保存的 `sessionStorage` cursor 不能证明对应聊天内容仍然存在；若冷启动把空数组与旧 cursor 组合，会永久跳过消息。本地缓存也不能替代服务端认证或使离线页面获得发送权限。

## Decision

1. 使用分会话的 `localStorage` 记录，在 Vue setup 阶段同步恢复项目身份和已读聊天。键隔离最近认证用户、项目、服务端 session、聊天 lane 和工作目录。每条记录原子保存内容、完整性标志、cursor、会话代数及阅读位置，不读取独立 cursor 作为恢复基线。
2. 缓存仅授权展示。认证未完成或断网时保留聊天和禁用的输入区域；明确的认证拒绝、账号变化会清除旧缓存、待发送队列和草稿，并废弃旧连接与异步写入，避免其他账号重放旧输入。恢复网络后重新认证。缓存不保存 cookie、token 或预渲染 HTML，也不向日志输出聊天正文。
3. 数组提交和 cursor 更新仅安排合并写入；支持时在 idle callback 中执行，后台切换和 pagehide 时补刷。存储不可用、记录损坏或版本不兼容时回退网络。单条记录限制为一百万 UTF-16 code units；空间不足只淘汰本缓存中的旧记录。不能通过截断内容却保留完整 cursor 来伪造基线。
4. 只有完整基线可以在初始 WebSocket 握手中携带 `afterSeq` 和 `laneGeneration`。服务端使用认证后解析出的 lane 检查代数、保留窗口与 cursor 上界。有效时返回 `historyMode: resume`，仍发送完成请求标识和必要运行态快照，但不发送历史；差异由现有 HTTP 增量路径补齐。
5. 无效基线返回 `historyMode: snapshot`，沿既有屏障提交权威历史后再释放并发实时事件与运行态快照。新连接可通过权威快照恢复服务端回滚后的较低代数，但连接内的过时代数仍被拒绝。不完整的流式冷缓存仅可读，不用于续传。重置和会话切换不继承旧基线。
6. 新请求预检使用已有的 `user` 事件向当前连接和同 lane 的连接发布增量，不再为同一请求额外保存和广播全量历史。没有增量发布能力的旧调用方保留历史回放后备路径。
7. 阅读位置保存首条已加载消息、可视锚点及偏移和是否跟随底部。只有首次挂载执行位置恢复；上翻历史继续使用 #228 的原生滚动锚定，不加入分页 scrollTop 补偿。
8. 保留正文与命令/patch 事件的独立额度，但两类事件被淘汰时均推进既有 `trimmed_through_seq`。省略历史后不能再假设命令装饰会由每次 bootstrap 补齐；只有错过淘汰事件的 cursor 才回退快照，已跟上的连接不受影响。合并快照的正常版本替换仍保留既有语义，不引入数据库迁移。

## Consequences

- 有效缓存可在首个应用渲染中可读，无变化重连不更新消息数组或 Markdown DOM；新增会话事件继续使用原有去重与排序约束。
- 清理浏览器站点数据、缓存额度限制、保留窗口过期或未建立缓存的首次访问仍需要网络快照。离线读取仅覆盖成功保留的内容，不承诺无限离线归档。
- 离线可读意味着当前浏览器配置文件中保留最近用户已读的聊天；共享设备应退出账号或清除站点数据。缓存不是新的认证凭据。
- 新握手字段是兼容性扩展；旧客户端仍收到历史，新客户端面对旧服务端仍可走原有回放路径。服务端不迁移数据库结构。
- 自动化覆盖真实 WebSocket / HTTP 同步、缓存首帧及滚动位置。Chromium 使用浏览器离线模式验证缓存 reload；当前 Linux Playwright WebKit 的离线开关导致导航内部错误，改用源站 HTTP 不可达验证 Service Worker shell 和本地聊天恢复，报告明确标注差异。两者均不能替代真实 iPhone 安装态 PWA 的离线生命周期、键盘和滚动验收。
