# ADR 0033: Isolate bounded Reviewer inspection

## Status
Accepted

工具总轮数和累计探索配额已由 [ADR 0038](0038-progress-based-execution.md) 替代；本文的权限与隔离约束保持不变。

## Context
Reviewer 需要主动检查关联源码，但通用 Agent 会话可能暴露 shell、写入或其他工具，不能仅靠提示词保证只读。

## Decision
Reviewer 使用独立 HTTP completion 循环，只注册 `read_file_range`、`search_code`、`list_dir`。模型、推理强度与角色指令每次从数据库角色配置读取；模型连接按任务所有者解析，不复用 Developer 会话。

工具读取已捕获的精确 Git commit，而不是可变工作区。宿主通过固定参数的 Git 子进程读取 regular blobs，不执行 shell、textconv 或子模块，不暴露任意命令。路径穿越、符号链接及常见凭据文件被拒绝；这不是通用操作系统沙箱。

默认允许五个工具回合，同一回合可以请求多个工具，由宿主串行执行，不设置每回合四次调用的门槛。资源约束使用已有的回合数、累计工具输出预算、单次输出与参数大小限制及整体超时。回合或输出预算耗尽后移除工具，要求最终 JSON；一批调用中途耗尽输出预算时，为剩余调用返回对应 `tool_call_id` 的未执行说明，不继续访问文件。

取消与超时传播至 HTTP 和 Git 子进程，结束时释放消息与索引缓存，不创建临时工作区或持久会话。只有合法的结构化判定才是代码审查结果；无效 JSON、判定结构错误、输出截断、工具关闭后仍要求调用工具及响应大小超限均抛出带明确原因的协议错误，不构造虚假的 `unknown/blocker` 缺陷。错误仅包含固定诊断及长度、结束原因等元数据，不包含模型响应正文。

Reviewer 执行失败按基础设施故障进入 `blocked`，保留现有返工计数及尝试账本，不自动重跑 Developer。真实的 `REJECT` 判定仍沿既有有界代码返工流程处理；本次修正不改变 diff 证据检查的既有判定规则。

### 2026-09-30 修正

此前的每回合四次限制会在模型正常请求六个只读工具时，将空字符串交给判定解析器，伪装成 JSON 解析错误并消耗代码返工预算。移除该局部门槛，而不是换成另一个任意调用次数。上述 Reviewer 执行错误分类取代早期将全部 Reviewer 错误交给 Developer 返工的约定。

### 2026-10-04 修正：请求拒绝与快照不可用（Issue #513）

- 请求级问题通过单次工具响应反馈具体原因，不设置整轮阻塞标记。路径缺失或拼写错误、
  无效参数、范围或分页游标越界均允许模型修正后继续检查；路径越界、敏感文件、
  非普通文件及未注册工具仍然拒绝，不增加任何读取或执行权限。
- `read_file_range` 每次最多读取 200 行，仍限制为 1 MiB 内的普通文件；先把
  `end_line` 截到文件末尾，再检查实际行数。超出行数预算时明确报告上限，输出仍受
  单次字符限制约束。模型若无法取得判定所需的内容，仍须返回 `INCOMPLETE`。
- `search_code` 与 `read_diff` 共用字符分页协议：`offset`、`content`、
  `next_offset`、`done`、`total_chars`。每页最多 1000 个字符，后续页须保持查询和
  路径模式不变；结果过多时建议缩小路径模式，而不是把结果量当成快照故障。
- 搜索覆盖索引中所有符合路径和文件大小约束的普通文件，不再静默限制为前 512 个。
  Git 输出流读至结束以核对退出状态，但内存只保留当前页，不缓存完整结果。
  因此取消了 64 KiB 搜索输出缓冲区上限；Git 超时、取消和权限约束保持有效。
  分页会重复读取同一不可变提交，这是有界内存与实现简洁性的取舍。
- Git 启动失败、提交或对象不可读、快照索引超过容量限制及 Git 操作超时仍设置
  整轮快照不可用标记；后续成功调用不能清除它。终态判定解析后仍检查该标记，
  并抛出 `ReviewerIncompleteError`，按基础设施故障进入 `blocked`，不记录虚假判定、
  不消耗 Developer 返工次数。取消和调用协议错误继续走既有独立错误路径。
- 本次不调整队列占用规则，不重试或修改生产任务，不涉及部署和发布。

## Consequences
审查证据与提交保持一致，不受工作区变化或符号链接替换影响。未提交文件、被排除文件及超限内容不能检查，模型必须明确证据缺口。

Reviewer 配置必须具有可供现有 HTTP completion 客户端使用的模型连接与凭据；仅有 Codex CLI 登录不保证可用。不回退到带任意工具的 Agent 会话。Developer 仍使用所选运行时，本决策不改变队列串行执行和合并收尾规则。
