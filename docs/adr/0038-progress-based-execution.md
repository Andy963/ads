# ADR 0038：用无进展检测代替工具总轮数配额

- 状态：已接受并实现
- 替代：ADR 0013 的工具总轮数策略，以及 ADR 0033 的累计探索配额

## 决策

Native 的 `maxToolRounds`、`ADS_AGENT_MAX_TOOL_ROUNDS` 和旧别名不再终止执行。Reviewer 的正整数工具轮数配置同样忽略，显式 `0` 仍禁止探索。网络重试、只读工具超时、取消、权限、Reviewer deadline 和自动返工授权上限保持不变；长命令采用下述会话化执行。

## 命令等待与执行期限分离

事故中模型为全量测试传入 `timeout_ms: 180000`，旧 runner 按 wall-clock 强杀测试，并非 Reviewer 的 30 分钟期限触发。只提高默认值不能修复显式短超时。

Native `exec_command` 改为 turn 内拥有的进程会话，默认等待 10 秒后返回句柄。`wait_command` 只等待和读取，不重放副作用；`cancel_command` 显式终止。旧 `timeout_ms` 兼容为有界等待参数，不再杀进程；真正的可选执行期限使用 `max_runtime_ms`，默认不设，模型只应在用户或策略明确要求时设置。共享 `runCommand` 的基础设施／只读调用不改变。

每个 turn 最多保留 16 个待收取命令，取走最终结果立即释放容量。该限制针对并发资源，不限制累计命令数。Linux 使用独立进程组；取消先发 SIGTERM，宽限后清理仍存活的进程组，即使 shell 先退出也不能遗漏忽略信号的子进程。异常、取消、重置均释放会话；恢复仅读取历史，不会将旧 session id 当成可重放执行请求。

运行中的等待由执行器验证并标注，才可豁免防循环；包含此类等待的周期（例如等待与读取未变化日志交替）不能证明执行状态没有进展。工具 JSON 与命令事件明确区分运行中和最终退出，运行中不写入已完成命令证据。模型在仍有待收取命令时给出最终答案，控制器追加显式等待调用与配对结果（不复用 Responses 的 opaque 输出），收集真实结果后再请求模型总结，避免将后台测试当作已通过。

每条输出流内存有界，只向模型输出脱敏后的完整行；跨写入的凭据不会在部分行轮询中暴露，超长行丢弃并标记截断。PEM 私钥在分行／截断之前按流保留脱敏状态，即使头部跨写入或被截断、主体跨多次轮询、结束标记缺失，也不会输出后续私钥主体。静默和等待都不是无进展证据。

共享防循环器记录最近 64 次操作的带盐 HMAC，不记录原始参数／结果。参数键排序后，与结果及相关资源版本共同指纹化。相同操作或 2–4 步周期重复三次时提醒，持续到五次且资源状态可验证时暂停。重复调用的 ID、命令耗时不是进展。文件读取使用文件内容和修改时间，未截断检索使用完整查询结果，归档历史页不可变；Reviewer 使用固定 commit。未知 shell／外部状态只提醒，不把正常等待误判为死循环；这不是能证明所有程序终止的通用算法。仅调用方已确认的等待操作可以豁免，不能靠工具名称申请豁免。

Native 暂停以既有 `interrupted` 状态及明确的错误原因持久化，不伪装成完成。检测历史随 checkpoint 保存；恢复只加载记录，绝不重放工具。明确清空会话才丢弃记录，任务自然完成后开始新的检测周期。

## 上下文与存储

模型上下文和原始执行证据分离。schema migration 32 增加追加式 chunks 与 projection cursor，旧记录原样纳入归档。每次 checkpoint 只追加新增消息和产物；摘要时才替换模型 projection。writer lease 与 reset fencing 同时覆盖新写入路径，chunks 随所属 turn 删除。既有整轮更新 API 保留兼容语义。

在完整工具批次边界，达到配置模型输入预算的安全比例时（计入 usage 校准，不另设隐藏消息数门槛），进行一次禁用工具的摘要请求。保留原始用户任务、摘要中的决策／已完成变更／测试证据／未完成项，以及最近两个完整工具批次。调用和结果不能拆开，旧 Responses opaque metadata 不进入合成摘要。摘要失败、输出截断或不能缩小上下文时安全暂停，不循环重试摘要。

持久会话可通过绑定当前 transcript 的 `read_execution_history` 分页获取已脱敏证据，不能指定其他会话。返回的历史不包含 opaque reasoning。禁用持久化的临时会话只保留内存摘要，不宣称有完整持久历史。摘要是有损的，关键决策必须能够回查原始证据。

## Reviewer

初始 diff 的 1,500 行限制改为预览大小，并用 40,000 字符约束单行异常大的预览，不是审核终止条件。大 diff 使用 `read_diff` 按字符分页，控制器要求连续覆盖全部过滤后 diff 才接受判定，单个超长行也可以翻页。只读文件工具的单次尺寸／超时及 secret／symlink 防护不变。

`INCOMPLETE` 是控制层错误，不是第三种代码判定。证据缺失、未读完整 diff、防循环暂停、协议／网络故障均阻塞审核，不写入 PASS／REJECT，也不消耗开发返工次数；只有有效代码 REJECT 才进入原返工流程。

## 验证重点

- 1,000 次有新证据的调用越过旧配额；模型上下文和检测器保持有界。
- 重复读取／周期循环先提醒再暂停，资源变化与明确等待不误判。
- 长任务压缩后可恢复，原始证据完整，副作用不重放。
- Chat／Responses 调用配对、opaque scope、凭据脱敏保持不变。
- 摘要中取消／重置／失败，以及 writer 被替换时不能落入完成状态。
- Reviewer 超过十轮、超过 40,000 字符和 1,500 行仍可继续；未完成审核不花返工次数。
