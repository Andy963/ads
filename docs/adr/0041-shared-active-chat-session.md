# ADR 0041: 跨设备共享项目的活动聊天会话

## Status

Accepted — Issue #521

## Context

同一会话的消息已有服务端广播，但新建 Actions 会话只重绑定发起端，其他在线设备
会留在旧 history key。仅同步项目记录或重连本端不能修复在线订阅分叉。

## Decision

- 已注册项目的 `web_projects.chat_session_id` 是该认证用户在该项目的活动 Actions
  会话选择。Acopilot 和使用 Bearer 认证的独立 channel connector 保持独立；不同账号
  和项目之间不传播选择。
- 项目存储在选择改变后发出数据库实例内的通知。WebSocket 服务订阅通知，通过原有
  连接消息链重绑定在线同作用域连接，发送 `welcome` 与权威历史快照，不增加轮询或
  第二套消息同步协议。快速连续更新按服务端当前选择丢弃过时通知。
- 发起端通过 `switch_chat_session` 完成远端选择，不并发发送 PATCH。客户端保留
  尚未确认的新建会话意图，断线后重新发送显式切换；普通重连不能用旧缓存覆盖服务端。
- 已注册项目的握手解析当前服务端选择。缓存会话不同则忽略旧 cursor，以快照建立
  新基线。收到跨会话 `welcome` 后，客户端清除旧输入/outbox、切换 transcript 与
  sequencer，并仅在本地保存新的项目选择，避免反向 PATCH 循环。
- 新客户端在会话相关输入中附带 `chat_session_id`。服务端在预检前校验作用域，
  不能将已经在网络中飞行的旧输入应用到新会话。重绑定排队期间拒绝旧端输入并中断
  旧执行；新建端紧接切换发送的输入在切换之后校验。已接收的旧会话历史仍保留。
- 原有 generation、幂等消息标识、重放 cursor 和快照排序屏障继续生效。通知监听在
  WebSocket 服务关闭时释放；连接关闭时删除重绑定回调。重绑定失败通过重连重新
  取得服务端选择，不保留一条已知分叉的连接。

## Consequences

同账号同项目的 Actions 会话选择不再是每设备独立的视图。此通知面向当前单进程服务，
不是多进程数据库变更订阅；若未来支持多个服务进程，需要跨进程通知机制。

未注册项目及不携带新作用域字段的旧客户端保留兼容入口；旧客户端无法提供网络中
迟到输入的会话归属证明。没有新增数据库结构或历史迁移。

验证覆盖真实双 WebSocket 的双向消息、切换后的持续广播、过时重连、消息幂等性、
排队重绑定、迟到旧输入、快速选择更新与账号/项目/Acopilot 隔离，以及客户端的
快照绑定、旧 outbox 清理和断线期间的新建意图。
