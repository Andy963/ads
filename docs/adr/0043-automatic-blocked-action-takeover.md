# ADR 0043: 由 Acopilot 自动接管阻塞任务

## Status

Superseded by ADR 0045

## Context

ADR 0040 的 Developer 有界监督仍然有效，但返工停止后只有 Actions 日志，
主 Agent 不会自动开始诊断。用户要求优先补齐自动接管，明确禁止绕过 Review。

## Decision

- 每次进入 blocked，在同一数据库事务中持久化一份不可变交接证据，包含原 Issue
  快照、尝试记录、执行步骤、审查结论、角色配置和 Git/PR 身份。
- 交接由服务端投递到现有持久化 Prompt Queue，实际触发所属用户、项目的 Acopilot
  执行，不依赖浏览器在线或人工发送消息。交接使用稳定消息 ID；广播、历史回放和
  多标签页不产生额外执行。排队消息可以跨进程恢复。
- Acopilot 诊断期间保持规划角色，不编辑工作区、不合并、不关闭 Issue。
  自动接管回合使用运行时只读能力限制，禁止写文件、执行交付命令或从输出触发 ADR/定时任务写入。
  自动接管只复用现有任务队列、Agent 回合和受限工具入口，不引入 MCP 调用或清单前置检查。
  本次自动接管授权允许它通过现有派发工具，为同一 Issue 创建一个关联的修复任务。
  只有服务端验证的交接执行上下文拥有此权限；模型参数不能声明或扩大该权限。
- 后续任务保留原验收快照、功能分支、基础提交和角色配置。主 Agent 的定点指导单独
  保存，不覆盖原 Issue 契约。旧 blocked 记录和失败账本保持可审计，人工出口仍只有 Dismiss。
- 每个根任务最多自动创建两个修复轮次，不因更换 job ID、重新启动或重复工具调用清零。
  预算耗尽后仍唤醒 Acopilot 给出诊断，但不再允许派发。没有增加 Reviewer 放行或覆盖接口。
- 每个后续 Developer 执行独立获得新的监督上下文，必须重新验证、独立 Review，
  并取得本次执行中确切 base/head 的 PASS 后才能使用确定性交付流程。
  已继承的 PR 即使显示已合并，也不能靠 GitHub 状态对账把旧 blocked 记录或未执行的修复任务
  标记为完成；必须核实并完成交付收尾。
- 原 Developer 及其子任务退出、工作区锁释放后才能交接。恢复派发要求干净的 dev
  或原功能分支，不执行 reset、clean、stash 或丢弃未提交修改。Acopilot 执行结束后才启动修复。
  异步预检返回后、实际取得工作区锁后再次校验身份、世代、任务状态及现场，不复活已取消的任务。
- 当前任务的关联修复优先于无关排队任务。已交接的 blocked 祖先不重复占用队列，
  但未解决的阻塞、失败或取消的后续任务仍然阻止无关任务越过现场。
- 所属项目移除、Actions 或 Acopilot 世代失效后，交接权限失效，不迁移到其他用户或新会话。
  中断中的 Acopilot 执行遵循已有 Prompt Queue 显式重试契约，不无限自动重放副作用。

## Consequences

本决策补充 ADR 0040 的执行结束边界，不改变它的 Review、精确提交授权和取消规则。
普通修复无需人工逐轮派遣；预算耗尽、工作区不安全、外部凭据缺失或主 Agent 自身执行失败
仍会明确停下并保留诊断，不能承诺所有任务必然自动完成。先完成当前 Issue 的有界恢复，
不在本决策中实现无限扫描 GitHub 待办或绕过未解决任务的全自动后台流程。
