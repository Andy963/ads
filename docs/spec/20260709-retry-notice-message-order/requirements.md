# 重试提示聚合与消息顺序修复需求

## 背景

上游模型出现临时错误时，系统会自动重试。当前每次重试失败都会进入普通聊天错误通道，导致聊天记录里连续出现多条相同错误，例如 high demand 或 429。与此同时，执行命令预览可能被插入到最新用户消息之前，造成时间顺序错误。

## 目标

1. 自动重试期间的临时上游错误只显示为一条可更新提示。
2. 提示需要显示累计次数，让用户知道系统正在重试。
3. 如果重试后成功，临时提示应随本轮临时状态一起清理。
4. 如果最终失败，临时提示应被最终错误替换，不重复显示同一类错误。
5. agent 执行命令预览必须显示在触发它的用户消息之后。

## 非目标

1. 不改变上游重试次数配置。
2. 不改变重试安全规则，例如已经发生副作用后不重试。
3. 不改变用户显式执行命令的持久化行为。

## 验收标准

1. 连续收到多条 transient retry 错误时，聊天列表只保留一条错误提示，并更新计数。
2. 收到最终 result 或最终 error 后，transient retry 提示被清理。
3. 当前回合的 execute 预览插入在最新用户消息之后，即使上一轮还有历史 execute 或 live block。
4. 前端测试覆盖 retry notice 聚合与 execute 排序。
5. `npx tsc --noEmit`、`npm run lint`、`npm test`、`npm run build` 通过。
